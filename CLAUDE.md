# PyTES

PyTES is an open-source Python library of models and auxiliary tools for **heat batteries**
(thermal energy storage), with **PyBaMM as the backend**. What PyBaMM is to batteries, PyTES
aims to be to TES. Licence: BSD-3. The maintainer is a PyBaMM contributor; assume deep PyBaMM
knowledge and discuss internals freely.

Read `docs/design/DESIGN.md` before any design-affecting work. It records what is **decided**
(do not reopen without being asked), **deferred** (with hooks that must exist now) and **open**.

## Scope rule

PyTES covers systems where **a heat transfer fluid (HTF) passes through or around a separate
storage medium**: finned or tubed PCM blocks, encapsulated PCM beds, sensible packed beds.
Sensible-only storage is in scope. The HTF may later be a refrigerant.

Out of scope: a general framework for arbitrary physics (people use PyBaMM directly for that;
composing PyTES submodels is in scope, see `DESIGN.md` D3), stratified
tanks, thermochemical storage, system-level models (heat pump, building).

## Non-negotiables

- PyBaMM is the backend and is never hidden. Users must be able to apply PyBaMM tools
  (solvers, `Simulation`, `QuickPlot`, PyBOP) directly to PyTES models.
- Follow PyBaMM conventions: parameter names with units (`"PCM latent heat [J.kg-1]"`),
  NumPy docstrings, `default_*` properties.
- Models are **fixed compositions of inspectable submodels** for a given set of options.
  `model.submodels` must be exposed. Variants are chosen through `options`; incompatible
  options raise, never swap submodels silently. Advanced users may build models from submodels
  through the public composition API (D3), with the same wiring checks.
- Every model must pass the **conformance suite** (`tests/conformance/`). The suite is the
  executable contract. **Where prose and tests disagree, the tests win** (then fix the prose).
- **Temperatures are in K.** Celsius variables are generated by a shared helper, never written
  by hand in a model. Temperature differences use separate K-only names.
- Power is positive on discharge and is defined from fluid enthalpy, `mdot * (h_out - h_in)`,
  never as `mdot * cp * dT`.
- The fluid-property object is the only way a model obtains fluid properties (`h`, `T`, `rho`,
  `c_p`, `k`, `mu`, as functions of `(h, p)`). The heat transfer coefficient is not a fluid
  property: it lives in the coupling's surface flux law. No hard-coded `cp` or constant
  coefficients inside submodels.
- Exact discrete energy conservation is a tested invariant. Do not weaken it to a tolerance
  without logging a finding.
- PyBaMM workarounds live **only** in `src/pytes/compat/`, each tagged with the upstream issue
  and a removal condition.
- Do not change the contract (variable names, units, sign, parameter names, submodel
  interfaces) without logging an entry in `docs/design/findings.md`.

## Working style

- One bounded task at a time (see the stage briefs in `DESIGN.md`). Each ends with a passing
  suite and an updated design doc.
- When a task changes a decision, update `DESIGN.md` in the same change and say so. The
  maintainer reviews those diffs; design authority stays with the maintainer.
- When two codebases disagree, do not silently pick one. Append to `findings.md` with a
  verdict: *contract flaw*, *model flaw*, or *family-specific difference*.
- Do not write code for something marked **deferred** unless asked. Do keep its hook intact.
- Documentation is part of done: one short example notebook per capability.

## Layout and references

- Work in this repo. `../Sunamp-IAA` (composite family) and
  `../encapsulated-LTES` (encapsulated family) are **read-only references** pinned to
  known commits. Copy code from them deliberately, one piece at a time. Never edit them.
- Fast tests run by default. Slow tests (e.g. the 3D mush discharge, about 30 s) are marked
  `slow` and use a reduced mesh in the regular run.
- Tooling: `uv`, `ruff`, pre-commit, pytest.
- Supported Python: every version PyBaMM supports, tested in CI (`.github/workflows/tests.yml`).
- Supported PyBaMM: releases of the last 3 months (CalVer). CI against the latest release is
  blocking; CI against PyBaMM `main` is non-blocking.
